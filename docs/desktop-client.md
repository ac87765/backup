# 加密备份桌面客户端：安装与使用说明

本文面向使用 Windows 或 macOS 客户端的用户。客户端与网页版使用同一账号、同一套端到端加密数据：
文件名和文件内容在客户端 / 浏览器内加解密，服务端只保存密文与必要元数据。

- Windows 真机验收清单：[`docs/acceptance/windows.md`](acceptance/windows.md)
- macOS 真机验收清单：[`docs/acceptance/macos.md`](acceptance/macos.md)
- macOS 开发 / 交接说明：[`docs/macos-handoff.md`](macos-handoff.md)

## 1. 从哪里下载

桌面客户端目前通过 GitHub Actions 的构建产物分发，之后的正式版本会放到 Releases 页面。

1. 打开仓库的 **Actions** 页面，选择工作流 **“Client (Flutter / bridge / desktop)”**。
2. 选择 `main` 分支最近一次成功的运行，或 `v*` 标签对应的发布运行。
3. 在页面底部的 **Artifacts** 下载：
   - Windows：`encrypted-backup-windows`，解压后得到 `加密备份-<版本>-windows-x64.exe`；
   - macOS：`encrypted-backup-macos`，解压后得到 `加密备份-<版本>-macos.dmg`。
4. Actions artifact 默认保留 90 天；过期后重新运行工作流即可。也可以用
   `gh run download <run-id> -n <artifact 名称>` 下载。

安装包没有购买 Apple / Microsoft 的代码签名证书，首次打开会被系统提示，处理方法见下文。
“关于”页显示的版本号与提交号应与安装包文件名中的版本一致。

## 2. Windows 安装

系统要求：Windows 10 / 11，x64。

1. 运行 `加密备份-<版本>-windows-x64.exe`。
2. 如果出现 **“Windows 已保护你的电脑”**（SmartScreen），点 **“更多信息”**，再点 **“仍要运行”**。
   这是未签名应用的正常提示，不是安装包损坏。
3. 安装程序按当前用户安装，**不需要管理员权限**，默认目录为
   `%LOCALAPPDATA%\Programs\加密备份`。也可以点“浏览”换到当前用户可写的其他目录。
4. 可选择是否创建桌面快捷方式；开始菜单中总会创建“加密备份”。安装完成页可以勾选
   **“立即启动加密备份”**。
5. 如果应用已经在运行，安装程序会提示先退出；从托盘菜单选择“退出”后重试即可。

升级：先退出正在运行的客户端，再运行新版本安装程序覆盖安装。应用数据、登录状态与备份配置都会保留；
“应用和功能”中不会出现重复条目。

## 3. macOS 安装

系统要求：Flutter 3.47.7 支持的 macOS（Apple Silicon / Intel 均可，但构建产物架构不同）。安装包由 CI 的 macOS 运行器构建，ad-hoc 签名，**未做 Apple 公证**。

1. 双击打开 `加密备份-<版本>-macos.dmg`。
2. 把 **“加密备份.app”** 拖到 dmg 窗口中的 **“应用程序”** 快捷方式，然后推出 dmg。
3. 首次打开会被 Gatekeeper 拦截。任选一种方式：
   - 在“访达”中右键（或按住 Control 点击）应用 → **“打开”** → 在对话框中再次点 **“打开”**；
   - 若右键菜单没有“打开”，到 **系统设置 → 隐私与安全性**，在页面下方点 **“仍要打开”**；
   - 或在“终端”执行
     `xattr -dr com.apple.quarantine "/Applications/加密备份.app"`，再双击打开。
4. 不要直接从 dmg 里运行应用；先拖到“应用程序”，否则更新时容易留下两份不同版本。

### 架构（Apple Silicon / Intel）

Flutter 的 macOS release 默认**只构建构建机当前的架构**，不是 universal：

- CI 的 `macos-latest` 是 Apple Silicon，产物为 **arm64**；
- 在 Intel Mac 上本地构建则得到 **x86_64**；
- universal（arm64 + x86_64）需要额外用 xcodebuild 指定 `ARCHS="arm64 x86_64"`，当前 CI 不生成。

在 Mac 上核对：

```bash
lipo -archs "/Applications/加密备份.app/Contents/MacOS/加密备份"
```

输出 `arm64` 表示 Apple Silicon 版；`x86_64` 表示 Intel 版。CI 日志中也会打印同一命令的结果。
Intel Mac 无法运行只有 arm64 的产物；遇到这种情况请记录并让审查者提供 x86_64 构建。

### 更新 macOS 版

退出应用，把新的“加密备份.app”拖到“应用程序”覆盖旧版本。由于 ad-hoc 签名每次构建都不同，
更新后首次读取钥匙串时系统可能询问是否允许访问，选择 **“始终允许”** 即可（属预期）。

## 4. 首次登录与引导

1. 启动客户端，输入邮箱与密码登录。注册、忘记密码、恢复密钥重置都通过登录页上的链接在网页完成。
   密码只用于在客户端内派生密钥，不会保存到本地。
2. 待审核账号会看到“正在等待管理员审核”，此时没有上传、新建或备份入口；管理员通过后点“重新检查”。
3. 登录成功后会保存会话令牌（关掉应用后不用重新输入邮箱），但**默认不保存主密钥**。
   下次打开应用只需输入密码解锁。
4. 首次使用会出现引导：
   - 选择要备份的常用文件夹（桌面、文档等）或“其他文件夹”；
   - 选择是否开机自动启动、是否“在这台电脑上保持解锁”（两项默认都关闭）；
   - 可以跳过，之后在“备份文件夹”和“设置”中修改。

登录、解锁、待审核的具体交互以界面为准；开发者实现与测试见
`openspec/changes/add-native-clients/`。

## 5. 备份文件夹

在左侧导航进入 **“备份文件夹”**：

- **添加文件夹**：选择本地文件夹，可修改云端目标位置。默认目标是
  `全部文件 / 电脑备份 / <设备名> / <本地文件夹名>`。
- **自动备份**：文件系统监听约 5 秒防抖合并；启动时做一次全量核对，之后每 6 小时再核对一次。
- **增量与版本**：大小和修改时间都没变的文件直接跳过；修改时间变了但内容与云端当前版本相同的文件
  不产生新版本；内容确实变化才上传新版本，旧版本可在版本历史中恢复。
- **永不删除云端**：在本地删除或重命名文件不会删除云端内容，重命名表现为云端新增一个文件。
  需要删除云端文件时请在网页版或客户端文件页手动删除。
- **排除规则**：默认排除 `.DS_Store`、`Thumbs.db`、`desktop.ini`、`._*`、`~$*`、`.~lock.*#`、
  `*.tmp`、`*.part`、`*.crdownload`，不跟随符号链接 / 快捷方式；可以添加 glob 规则和排除子文件夹。
- **控制**：可以暂停 / 恢复全部备份、对某个文件夹“立即备份”，也可以在设置中限制上传速度。
- **状态与最近活动**：备份文件夹页显示已备份 / 正在备份 / 需要解锁等状态；托盘菜单也会同步显示。

第一次备份大目录需要扫描和计算哈希，可能较慢；之后只处理变化的文件。

## 6. 托盘（Windows）与菜单栏（macOS）

关闭主窗口**不会退出应用**，而是隐藏到托盘 / 菜单栏继续备份。真正退出请用托盘菜单中的 **“退出”**。

- Windows：任务栏通知区域（可能收在“^”里）的图标；macOS：菜单栏模板图标，深色 / 浅色菜单栏都能看清。
- 四种状态：**已全部备份**、**正在备份 n/m**、**已暂停**、**需要解锁**。
- 菜单项：状态文字（不可点）、暂停 / 恢复备份、打开应用、打开网页版、设置、退出。
- 左键单击图标打开主窗口；需要解锁时直接打开解锁页。
- 第一版使用系统原生菜单，不做 `design/desktop/tray.html` 的富弹窗；进行中的传输和最近活动在主窗口查看。

## 7. “保持解锁”的风险

“在这台电脑上保持解锁”默认关闭。开启后，主密钥交给操作系统保管：

- Windows：DPAPI（当前用户）加密后存入凭据管理器；
- macOS：Keychain，`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`（不进 iCloud、不进系统备份）。

**风险：任何能登录这台电脑系统账号的人，都可能读取你的备份内容。** 这会把端到端加密的保护范围
从“知道密码的人”缩小到“能登录这台电脑的人”。共用电脑、系统账号没有锁屏密码、或电脑可能被他人
物理接触时，不要开启。

关闭时，重启应用后备份会暂停，托盘显示“需要解锁”，输入密码后继续。
开启“保持解锁”并同时开启“开机自动启动”，系统重启后才能真正自动继续备份。

退出登录、修改密码或服务端使会话失效时，客户端会清除会话令牌与保存的主密钥。

## 8. 开机自动启动

在 **设置** 中开启“开机自动启动”（默认关闭）。开启后：

- Windows：写入当前用户注册表
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的值 **“加密备份”**；
- macOS：登记为当前用户的 Login Item；
- 启动参数为 `--background`，只启动到托盘 / 菜单栏，不弹出主窗口；
- 启动本身不涉及密钥。未开启“保持解锁”时，托盘会提示“需要解锁才能继续备份”，点击后打开解锁页。

关闭开关会删除对应的开机启动登记。卸载程序也会删除 Windows 的该 Run 值。

## 9. 数据与凭据存放在哪里

客户端不会把文件明文缓存到应用数据目录；下载的明文直接写到用户选择的目标路径。

### Windows

| 内容 | 位置 |
|---|---|
| 程序文件 | `%LOCALAPPDATA%\Programs\加密备份`（安装时可改） |
| 应用数据 | `%APPDATA%\Encrypted Backup\加密备份` |
| 本地状态库 | 上述目录中的 `client-state.sqlite3`（备份文件夹配置、文件索引、续传记录、最近活动；不含密钥和文件内容） |
| 界面设置 | 上述目录中的 `desktop-settings.json`（是否完成引导、是否提示过关闭到托盘） |
| 会话令牌 | 凭据管理器 → Windows 凭据 → 普通凭据，目标名 `EncryptedBackup/session-token` |
| 保存的主密钥 | 同上的 `EncryptedBackup/master-key`（仅在开启“保持解锁”后存在） |
| 开机启动 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的值 `加密备份` |

本地状态库中的本地路径是明文，只保存在本机（与系统文件索引同等级别），不会上传；云端文件名仍是密文。

### macOS

| 内容 | 位置 |
|---|---|
| 程序文件 | `/Applications/加密备份.app` |
| 应用数据 | `~/Library/Application Support/com.encryptedbackup.client`（`client-state.sqlite3`、`desktop-settings.json`） |
| 会话令牌 / 主密钥 | 钥匙串访问中的服务 `com.encryptedbackup.client`，账户 `session-token` 与 `master-key` |
| 开机启动 | 系统设置 → 通用 → 登录项中的“加密备份” |

## 10. 卸载与彻底清除

卸载客户端**不会删除云端备份**。云端数据需要在网页版中管理；卸载也不会自动删除本机应用数据与系统凭据，
以便重装后恢复配置和登录状态。

### Windows

1. 先在应用内 **设置 → 退出登录**（会删除凭据管理器中的会话令牌与主密钥）。
2. 从托盘菜单 **退出** 应用。
3. 打开 **设置 → 应用 → 已安装的应用 → 加密备份 → 卸载**，或使用开始菜单中的卸载快捷方式。
4. 卸载程序会删除程序文件与开机启动 Run 值，并弹窗说明保留了什么。
5. 如需彻底清除，再手动删除数据目录 `%APPDATA%\Encrypted Backup\加密备份`。
6. 如果卸载前没有退出登录，到 **控制面板 → 凭据管理器 → Windows 凭据 → 普通凭据**，删除
   `EncryptedBackup/session-token` 与 `EncryptedBackup/master-key`。也可以在命令提示符执行：

   ```bat
   cmdkey /delete:EncryptedBackup/session-token
   cmdkey /delete:EncryptedBackup/master-key
   ```

### macOS

1. 先在应用内退出登录；从菜单栏菜单选择 **退出**。
2. 在 **系统设置 → 通用 → 登录项** 中移除“加密备份”（如果开过开机启动）。
3. 打开“访达” → “应用程序”，把“加密备份.app”拖到废纸篓并清空。
4. 删除数据目录 `~/Library/Application Support/com.encryptedbackup.client`。
5. 打开“钥匙串访问”，搜索 `com.encryptedbackup.client`，删除 `session-token` 与 `master-key` 两个条目。

## 11. 常见问题

**托盘显示“需要解锁才能继续备份”**
：这是正常的。未开启“保持解锁”时，重启应用 / 重启电脑后主密钥不在内存中，备份会暂停。
点击托盘图标或打开应用，输入密码解锁即可继续。

**文件正在被其他程序使用，无法备份**
：客户端以共享读方式打开文件；如果其他程序以独占方式锁定了文件，本次会失败并稍后重试，
其他文件不受影响。关闭占用程序后可以点“立即备份”，或等待下一次自动核对。
如果文件在上传过程中被修改，客户端会放弃本次上传，稍后按新内容重试，不会上传半个文件。

**磁盘空间不足**
：下载会先在目标目录写临时文件，校验通过后才原子重命名，因此目标盘需要有足够空间；
本地状态库和备份索引也需要少量空间。云端配额不足时，传输列表会显示错误，清理回收站或升级配额后重试。

**Windows 提示“Windows 已保护你的电脑”**
：见第 2 节，选择“更多信息 → 仍要运行”。这是未签名应用的正常提示。

**macOS 提示“无法打开，因为 Apple 无法检查其是否包含恶意软件”**
：见第 3 节，右键“打开”或在“隐私与安全性”中允许，或执行 `xattr` 命令。

**上传很慢 / 一直显示“等待限流”**
：服务端限流时客户端会按 `Retry-After` 自动退避，不把限流算作失败。大量小文件首次备份较慢是正常的；
可以在设置中限制上传速度，避免占满带宽。

**怎么确认版本**
：设置 → 关于 中显示版本号和对应的 Git 提交；应与下载的安装包文件名、Actions 运行记录一致。

**换电脑 / 重装后数据还在吗**
：云端数据仍在，登录同一账号即可看到。只保留本机应用数据不会同步到另一台电脑；
“保持解锁”的主密钥绑定当前系统账号，不会随 iCloud 同步。
