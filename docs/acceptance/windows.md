# Windows 真机验收清单（tasks 7.3）

> 在真实 Windows 10 / 11 x64 机器上执行。建议使用专用测试账号与测试文件夹，不要把真实密钥、
> 令牌或密码写进验收记录。勾选前必须实际执行并观察结果；失败项记录现象、复现步骤与相关日志
> （日志不得包含令牌、密钥、文件内容）。
>
> Spec 来源：`openspec/changes/add-native-clients/specs/native-clients/spec.md`。
> 每条末尾标注对应的 Requirement / Scenario；没有独立 Scenario 的安装、托盘行为标注为
> “安装约束 / design D10”或对应 Requirement。
>
> 本清单对应 tasks 7.3，由用户与审查者在真机上执行后再决定是否勾选；实现方不预先勾选。

## 0. 前置条件

- [ ] 准备一台 Windows 10 / 11 x64 真机，当前用户不是管理员也能安装。
- [ ] 从 CI（`main` 或 `v*` 标签的运行）下载 `encrypted-backup-windows` artifact，
      或由审查者在本机用 `apps/client/tool/package_windows.ps1` 生成安装包。
- [ ] 准备三个账号：已审核普通账号、待审核账号、管理员账号（用于审核待审核账号）。
- [ ] 准备测试文件：小文本、中文名文件、≥ 2 GB 大文件、带子目录的文件夹。
      确认测试账号的云端配额足够；配额不足时改用至少跨越 3 个 4 MiB 分块的文件，仍可验证断点续传。
- [ ] 能在同一台机器用浏览器登录网页版，核对同一账号的数据。
- [ ] 记录安装包文件名中的版本号，稍后与“关于”页比对。
- [ ] 记录初始状态：`%APPDATA%\Encrypted Backup\加密备份` 是否已存在、
      凭据管理器中是否已有 `EncryptedBackup/` 条目（全新机器应为空）。

## A. 安装、升级与卸载

### [ ] W-01 下载并安装 Windows 安装包

- **操作**：双击 `加密备份-<版本>-windows-x64.exe`；若 SmartScreen 出现，点“更多信息 → 仍要运行”。
  在向导中保留默认安装目录，勾选“创建桌面快捷方式”，完成页勾选“立即启动加密备份”。
- **预期**：
  - 安装过程不弹 UAC、不需要管理员密码；
  - 默认目录是 `%LOCALAPPDATA%\Programs\加密备份`（当前用户 Programs，而不是 `C:\Program Files`）；
  - 开始菜单出现“加密备份”与卸载快捷方式，桌面出现快捷方式，安装完成页勾选后应用启动；
  - “设置 → 关于”显示版本号与提交号，且与安装包文件名 / CI 运行记录一致。
- **Spec**：`Requirement: 构建与分发` → `Scenario: 下载 Windows 安装包`。

### [ ] W-02 安装 / 卸载时应用正在运行

- **操作**：先启动应用并保持运行；再次运行安装包。随后关闭应用重试；卸载时也先启动应用再运行卸载程序。
- **预期**：安装程序 / 卸载程序检测到单实例 Mutex，提示先退出“加密备份”；退出应用后重试成功，
  不会出现两个实例或损坏的安装。
- **Spec**：安装约束（design D10 / tasks 7.1）；Mutex 名与 `windows/runner/main.cpp` 一致。

### [ ] W-03 覆盖升级

- **操作**：在已安装并已登录的机器上，退出应用，运行同一版本或更新版本的安装包覆盖安装；再打开应用。
- **预期**：安装目录被覆盖、开始菜单 / 桌面快捷方式仍在；“应用和功能”中只有一条“加密备份”；
  登录状态、备份文件夹配置、本地状态库都保留；关于页版本更新。
- **Spec**：安装约束（design D10）；固定 AppId 的升级行为。

### [ ] W-04 卸载保留用户数据与凭据，并可手动清除

- **操作**：
  1. 卸载前记录 `%APPDATA%\Encrypted Backup\加密备份` 存在，且凭据管理器有 `EncryptedBackup/session-token`
     （开启“保持解锁”时还应有 `EncryptedBackup/master-key`）。
  2. 从“设置 → 应用 → 已安装的应用”卸载；观察完成页提示。
  3. 检查程序目录、开始菜单 / 桌面快捷方式，以及注册表
     `reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "加密备份"`
     （卸载后应返回“找不到指定的注册表项或值”）。
  4. 检查数据目录与凭据管理器条目是否还在（可运行
     `cmdkey /list | findstr EncryptedBackup`，应仍能看到两个条目）。
  5. 按提示手动清除：删除数据目录；在凭据管理器删除两个条目（或 `cmdkey /delete:...`）。
- **预期**：
  - 程序文件、快捷方式、Run 值“加密备份”被删除；Run 键与其他程序的值不受影响；
  - 数据目录与 `EncryptedBackup/session-token`、`EncryptedBackup/master-key` **保留**；
  - 卸载完成页明确说明保留内容与清除方法；
  - 按提示操作后数据目录与凭据条目消失。
- **Spec**：安装 / 卸载约束（tasks 7.1）；`Requirement: 保持解锁` 的凭据清除语义。

## B. 登录、待审核与解锁

### [ ] W-05 首次登录与“关于”信息

- **操作**：全新安装后启动，使用已审核账号登录；打开“设置 → 关于”。
- **预期**：登录成功进入文件页；关于页显示版本号、Git 提交；“设置 → 安全与隐私”能看到密钥边界说明；
  凭据管理器出现 `EncryptedBackup/session-token`，默认没有 `master-key`。
- **Spec**：`Requirement: 登录与解锁`（登录与钥匙串行为）；`Requirement: 保持解锁`。

### [ ] W-06 待审核账号没有写入口

- **操作**：退出登录，用待审核账号登录；观察页面与入口；让管理员在网页后台通过审核，再点“重新检查”。
- **预期**：显示“正在等待管理员审核”，没有上传、新建、备份文件夹等写入口；通过审核后“重新检查”进入文件页。
- **Spec**：`Requirement: 登录与解锁` → `Scenario: 待审核账号`。

### [ ] W-07 重新打开只需要密码解锁

- **操作**：关闭（退出）应用后重新启动；观察解锁页；输入密码进入文件页。
- **预期**：解锁页显示已保存的邮箱，不需要重新输入邮箱；输入错误密码有提示且不进入文件页；
  正确密码后进入文件页；凭据管理器中仍只有 `session-token`，没有保存 `master-key`。
- **Spec**：`Requirement: 登录与解锁` → `Scenario: 重新打开应用`。

### [ ] W-08 退出登录清除会话与主密钥

- **操作**：在设置中开启“保持解锁”（完成风险确认），确认凭据管理器出现 `master-key`；
  然后执行“退出登录”。
- **预期**：返回登录页；`EncryptedBackup/session-token` 与 `EncryptedBackup/master-key` 都被删除；
  重新打开应用需要输入邮箱与密码。
- **Spec**：`Requirement: 保持解锁` → `Scenario: 退出登录清除凭据`。

## C. 浏览与文件操作

### [ ] W-09 浏览、筛选、排序与解密名称

- **操作**：在网页版创建几个中文名 / 英文名文件与子文件夹；在客户端切换列表 / 网格、切换排序、按当前文件夹筛选。
- **预期**：客户端显示正确的明文名称与大小，不显示密文或乱码；排序与筛选生效；
  界面不出现任何密钥或可派生密钥的字段。
- **Spec**：`Requirement: 文件管理`；`Requirement: 密钥只在 Rust 核心中`（桥接边界由自动化测试覆盖）。

### [ ] W-10 新建、重命名、移动、删除、回收站与版本

- **操作**：在客户端新建文件夹、重命名文件、移动到另一文件夹；删除一个文件后到回收站恢复；
  在网页版上传同名新版本生成第二个版本，再在客户端版本历史中恢复旧版本；同时在网页版核对。
- **预期**：所有操作在客户端与网页版一致；删除后文件进入回收站，恢复后回到原位置；
  版本历史能列出并恢复旧版本；不会出现重复文件或丢失内容。
- **Spec**：`Requirement: 文件管理` → `Scenario: 删除并从回收站恢复`。

## D. 上传、下载与断点续传

### [ ] W-11 客户端上传、Web 下载（内容与 SHA-256 一致）

- **操作**：在客户端上传一个已知文件（建议同时测试中文名与带子目录的文件夹），在网页版下载；
  用 `Get-FileHash <文件> -Algorithm SHA256` 比较两端内容。
- **预期**：网页版能看到同名文件并成功下载；SHA-256 与原文件一致；上传进度、暂停 / 继续 / 取消 / 重试可用。
- **Spec**：`Requirement: 上传与下载`；`Requirement: 与 Web 互通` → `Scenario: 客户端上传、Web 下载`
  （该 Scenario 以 macOS 为例，Windows 走同一 API 与格式）。

### [ ] W-12 Web 上传、客户端下载（内容与 SHA-256 一致）

- **操作**：在网页版上传“合同.pdf”，在客户端打开同一文件夹并下载到本地；比较 SHA-256。
- **预期**：客户端显示同名文件，下载成功，SHA-256 与原文件一致；下载后的文件位于用户选择的目标路径。
- **Spec**：`Requirement: 与 Web 互通` → `Scenario: Web 上传、客户端下载`。

### [ ] W-13 重启后继续未完成的上传

- **操作**：上传 ≥ 2 GB 文件，在传输列表显示已上传一部分时，从托盘菜单退出客户端；
  重新打开并解锁，观察传输列表；等待完成并与原文件比较。
- **预期**：上传从已确认分块之后继续，而不是从 0 开始；完成后云端文件内容与原文件 SHA-256 一致；
  不产生重复文件；传输列表显示续传后的进度。
- **Spec**：`Requirement: 上传与下载` → `Scenario: 重启后继续上传`。

### [ ] W-14 下载整个文件夹到本地（保留目录结构）

- **操作**：在云端准备“照片”及多层子目录；在客户端选择“下载文件夹到本地”，指定一个空目录。
- **预期**：本地出现“照片”及完整子目录结构；每个文件与云端内容一致（抽样比较 SHA-256）；
  不留下临时文件；下载失败时目标位置不会出现半成品文件。
- **Spec**：`Requirement: 上传与下载` → `Scenario: 下载文件夹到本地`；
  `Requirement: 密钥只在 Rust 核心中` 的“解密失败不留部分明文”。

### [ ] W-15 拖拽上传

- **操作**：从资源管理器把单个文件、多个文件、一个文件夹拖到客户端文件页。
- **预期**：文件与文件夹都被上传，文件夹保留相对结构；拖拽有明确的悬停 / 成功反馈；
  拖入不支持的项目时不会崩溃。
- **Spec**：`Requirement: 上传与下载`（拖拽上传）。

### [ ] W-16 暂停 / 继续 / 取消 / 重试与 429 退避

- **操作**：上传若干文件时暂停、继续、取消一个传输、对失败项点重试；
  连续上传大量小文件触发服务端限流，观察传输列表。
- **预期**：暂停后进度停止、继续后恢复；取消会释放预留；重试成功；
  429 显示“等待限流”并按 `Retry-After` 自动退避，不把文件标记为永久失败。
- **Spec**：`Requirement: 上传与下载`（暂停 / 继续 / 取消 / 重试、429 自动退避）。

## E. 文件夹备份全流程

### [ ] W-17 添加备份文件夹与默认云端目标

- **操作**：进入“备份文件夹”，添加一个测试目录；查看默认目标位置，必要时修改；观察状态与最近活动。
- **预期**：默认目标是 `全部文件 / 电脑备份 / <设备名> / <本地文件夹名>`；可修改；
  界面明确说明“本地删除不会删除云端”；状态显示扫描 / 已备份。
- **Spec**：`Requirement: 桌面文件夹备份`；`Requirement: 备份排除与控制`。

### [ ] W-18 新增文件自动备份

- **操作**：在备份文件夹中放入一个新文件；等待数秒；在网页版对应云端目录查看。
- **预期**：文件自动出现在云端，名称与内容正确（Web 可解密）；托盘显示“正在备份”，完成后显示“已全部备份”。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 新增文件自动备份`。

### [ ] W-19 修改文件生成新版本

- **操作**：修改已备份文件并保存；在客户端 / 网页版打开版本历史；恢复旧版本。
- **预期**：云端新增一个版本，旧版本仍可查看与恢复；恢复后内容与旧版本一致；本地文件不会被立即覆盖
  （下一次扫描按内容决定是否上传）。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 修改文件生成新版本`。

### [ ] W-20 本地删除不影响云端

- **操作**：在本地删除一个已备份文件；等待监听与全量核对；在网页版查看云端文件。
- **预期**：云端文件保留、内容不变、版本不减少；客户端活动记录说明未删除云端。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 本地删除不影响云端`。

### [ ] W-21 内容不变不产生新版本

- **操作**：只修改文件修改时间、不改内容（例如
  `(Get-Item .\a.txt).LastWriteTime = Get-Date`）；等待自动核对与手动“立即备份”。
- **预期**：不产生新版本，不上传；本地索引更新（下一次不会重复计算 / 上传）；版本数量与内容不变。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 重复内容不产生版本`。

### [ ] W-22 排除临时文件与系统文件

- **操作**：在备份文件夹中创建 `report.docx.tmp`、`~$report.docx`、`Thumbs.db`、`.DS_Store`、
  `desktop.ini`、`._x`、`a.part`、`b.crdownload`，以及一个自定义排除子文件夹；等待扫描。
- **预期**：这些文件 / 子文件夹都不出现在云端；正常文件仍被备份；可在界面添加 glob 与排除子文件夹。
- **Spec**：`Requirement: 备份排除与控制` → `Scenario: 排除临时文件`。

### [ ] W-23 被占用文件与上传中被修改的文件

- **操作**：
  1. 用 Excel / Word 等程序打开备份文件夹中的文件并保持打开，修改并保存后观察备份；
  2. 用 PowerShell 以独占方式锁定文件：
     `$fs = [IO.File]::Open('C:\path\locked.txt','Open','ReadWrite','None')`，
     等待一次扫描，再 `$fs.Dispose()` 后点“立即备份”；
  3. 上传一个大文件时持续写入该文件，观察是否放弃并在稍后重试。
- **预期**：
  - 其他程序以共享读方式打开时，客户端仍能读取并备份；
  - 独占锁定时本次备份失败 / 延后，不影响其他文件；释放后自动或手动重试成功；
  - 上传中文件变化时放弃本次上传，稍后按新内容重试，云端不会出现截断 / 半文件。
- **Spec**：`Requirement: 桌面文件夹备份`；`Requirement: 上传与下载`（design D4：共享读、修改后重试）。
  无独立 Scenario，按 D4 验收。

### [ ] W-24 重命名只在云端新增，不删除旧内容

- **操作**：在本地把一个已备份文件改名；等待扫描；在网页版查看。
- **预期**：云端保留旧文件，并新增改名后的文件；不会删除旧版本或旧文件。
- **Spec**：`Requirement: 桌面文件夹备份`（本地删除或重命名 MUST NOT 删除云端内容）。

### [ ] W-25 暂停 / 恢复、立即备份与限速

- **操作**：暂停全部备份，放入新文件；确认未上传；恢复后确认上传；使用“立即备份”；
  在设置中设置上传限速并上传大文件。
- **预期**：暂停期间不产生新上传；恢复后继续；立即备份触发一次扫描；限速生效且界面有提示；
  暂停状态在托盘同步显示“已暂停”。
- **Spec**：`Requirement: 备份排除与控制`（暂停 / 恢复、立即备份、上传限速）。

## F. 托盘、后台运行与单实例

### [ ] W-26 关闭窗口后继续备份

- **操作**：点击窗口关闭按钮；确认进程仍在、托盘图标存在；向备份文件夹添加文件；再左键点击托盘图标。
- **预期**：窗口隐藏而不是退出；文件仍被备份；托盘图标显示正在上传，完成后“已全部备份”；
  点击图标恢复并聚焦主窗口。
- **Spec**：`Requirement: 托盘与后台运行` → `Scenario: 关闭窗口后继续备份`。

### [ ] W-27 托盘四种状态与菜单

- **操作**：分别制造 / 观察“已全部备份”“正在备份 n/m”“已暂停”“需要解锁”四种状态；
  打开托盘右键菜单，逐项点击“暂停 / 恢复备份”“打开应用”“打开网页版”“设置”“退出”。
- **预期**：图标、提示文字、菜单首行状态与四种状态一致；暂停 / 恢复生效；打开应用显示窗口；
  打开网页版用系统浏览器打开正确地址；设置打开设置页；退出结束进程并移除托盘图标。
- **Spec**：`Requirement: 托盘与后台运行`（四种状态与菜单项）。

### [ ] W-28 未解锁时托盘提示

- **操作**：关闭“保持解锁”，退出应用；重新启动（可配合开机启动）；观察托盘；点击托盘图标。
- **预期**：托盘提示“需要解锁才能继续备份”，备份暂停；点击后打开解锁页；解锁后状态恢复。
- **Spec**：`Requirement: 托盘与后台运行` → `Scenario: 未解锁时提示`。

### [ ] W-29 单实例

- **操作**：应用运行时再次双击开始菜单 / 桌面快捷方式（或直接运行 exe）。
- **预期**：不会出现第二个窗口、第二个托盘图标或第二个进程；已有窗口被恢复并聚焦。
- **Spec**：`Requirement: 托盘与后台运行`（重复启动 MUST 激活已有实例）。

## G. 开机启动与保持解锁

### [ ] W-30 开机自动启动（未保持解锁）

- **操作**：设置中开启“开机自动启动”，关闭“保持解锁”；注销 / 重启 Windows 并登录系统；
  观察应用与托盘。
- **预期**：应用自动启动且不弹主窗口（`--background`），托盘提示“需要解锁”；点击打开解锁页；
  解锁后开始备份；`reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "加密备份"` 能查到该值。
- **Spec**：`Requirement: 托盘与后台运行` → `Scenario: 未解锁时提示`；
  `Requirement: 保持解锁`（开机启动只启动程序，不涉及密钥）。

### [ ] W-31 保持解锁 + 开机启动自动继续备份

- **操作**：开启“在这台电脑上保持解锁”（阅读风险说明并确认）与“开机自动启动”；
  重启电脑并登录系统，观察托盘与备份；向备份文件夹加入文件。
- **预期**：应用自动启动、自动解锁，无需输入密码；备份继续进行，新文件自动上传；
  凭据管理器出现 `EncryptedBackup/master-key`（DPAPI 当前用户范围）。
- **Spec**：`Requirement: 保持解锁` → `Scenario: 开机后自动继续备份`。

### [ ] W-32 关闭保持解锁会移除主密钥

- **操作**：在设置中关闭“在这台电脑上保持解锁”；检查凭据管理器；重启应用。
- **预期**：`EncryptedBackup/master-key` 被删除；重启后需要输入密码解锁；会话令牌仍保留，邮箱不需要重输。
- **Spec**：`Requirement: 保持解锁`（默认关闭；关闭后不持久化主密钥）。

### [ ] W-33 关闭开机启动

- **操作**：在设置中关闭“开机自动启动”；检查注册表 Run 值；重启（可选）。
- **预期**：Run 值“加密备份”被删除（`reg query ... /v "加密备份"` 查不到）；重启后不自动启动；
  其他程序的开机启动项不受影响。
- **Spec**：`Requirement: 托盘与后台运行`（默认关闭的开机自动启动）。

## H. 与 Web 互通与恢复到电脑

### [ ] W-34 Web 上传 → 客户端解密下载

- **操作**：网页版上传一个文件（含中文名 / 特殊字符），客户端下载；比较 SHA-256。
- **预期**：客户端显示明文名称，下载内容与原文件一致；不出现乱码、重复文件或解密失败。
- **Spec**：`Requirement: 与 Web 互通` → `Scenario: Web 上传、客户端下载`。

### [ ] W-35 客户端上传 / 备份 → Web 解密查看

- **操作**：客户端上传一个文件；把备份文件夹中的文件自动备份到云端；在网页版打开并下载。
- **预期**：网页版能看到同一文件、同一版本状态，下载内容一致；回收站 / 版本状态与客户端一致。
- **Spec**：`Requirement: 与 Web 互通` → `Scenario: 客户端上传、Web 下载`；
  `Requirement: 桌面文件夹备份` → `Scenario: 新增文件自动备份`。

### [ ] W-36 恢复到电脑

- **操作**：在客户端选择云端文件夹“下载到本地”；对单个文件从版本历史恢复旧版本后下载；
  与网页版下载结果比较。
- **预期**：本地目录结构完整、内容一致；恢复的版本内容与网页版一致；目标目录没有临时文件残留。
- **Spec**：`Requirement: 上传与下载` → `Scenario: 下载文件夹到本地`；
  `Requirement: 文件管理`（版本恢复）。
