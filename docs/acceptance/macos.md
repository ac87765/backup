# macOS 真机验收清单（tasks 7.4）

> 在真实 Mac 上执行，优先在 Apple Silicon 机器验收；如有 Intel Mac，另做架构核对。
> 下载 CI 的 `encrypted-backup-macos` artifact 安装，不需要在 Mac 上安装 Xcode / Rust / Flutter。
> 勾选前必须实际执行并观察结果；失败项记录现象、复现步骤与日志（日志不得包含令牌、密钥、文件内容）。
>
> Spec 来源：`openspec/changes/add-native-clients/specs/native-clients/spec.md`。
> macOS 专有项来自 `docs/macos-handoff.md` 第 3 节。
>
> 本清单对应 tasks 7.4，由用户与审查者在真机上执行后再决定是否勾选；实现方不预先勾选。

## 0. 前置条件

- [ ] 仓库 Actions → “Client (Flutter / bridge / desktop)” → `main` 或 `v*` 标签的运行 →
      下载 `encrypted-backup-macos` artifact，解压得到 `加密备份-<版本>-macos.dmg`。
- [ ] 准备已审核账号、待审核账号、管理员账号；能在这台 Mac 用浏览器登录网页版。
- [ ] 准备测试文件：中文名、带重音字母（如 `é`）、小文本、≥ 2 GB 大文件、带子目录的文件夹。
      确认测试账号的云端配额足够；配额不足时改用至少跨越 3 个 4 MiB 分块的文件，仍可验证断点续传。
- [ ] 记录 Mac 芯片（ → 关于本机）与 macOS 版本；记录 dmg 文件名中的版本。
- [ ] 记录初始状态：`~/Library/Application Support/com.encryptedbackup.client` 是否已存在；
      钥匙串访问中是否已有服务 `com.encryptedbackup.client` 的条目。

## A. 安装、Gatekeeper 与架构

### [ ] M-01 打开 dmg、拖入“应用程序”并通过 Gatekeeper

- **操作**：双击 dmg，把“加密备份.app”拖到“应用程序”，推出 dmg；
  首次打开时按 `docs/desktop-client.md` 第 3 节操作：右键“打开”或在“系统设置 → 隐私与安全性”允许，
  必要时执行 `xattr -dr com.apple.quarantine "/Applications/加密备份.app"`。
- **预期**：应用能正常启动；不会提示“应用已损坏”；从“应用程序”启动而不是从 dmg 内启动；
  Gatekeeper 的“无法验证开发者”提示可以按文档绕过。
- **Spec**：`Requirement: 构建与分发`（macOS `.dmg`、ad-hoc 签名，design D10）。

### [ ] M-02 核对应用架构

- **操作**：执行
  `lipo -archs "/Applications/加密备份.app/Contents/MacOS/加密备份"`，并与 CI 日志中
  “打印应用架构”步骤的输出、Mac 芯片对照。
- **预期**：Apple Silicon 上为 `arm64`；Intel Mac 上为 `x86_64`（或 universal 同时含两者）。
  若 Intel Mac 得到 arm64，应用无法启动，记录为阻塞问题并让审查者提供 x86_64 / universal 构建。
- **Spec**：`Requirement: 构建与分发`（design D10 的构建架构说明）。

### [ ] M-03 覆盖升级与钥匙串提示

- **操作**：在已登录的机器上退出应用，把新版本拖入“应用程序”覆盖；首次打开并读取钥匙串。
- **预期**：应用正常升级，应用数据与备份配置保留；如果系统询问是否允许访问钥匙串，选“始终允许”
  后可以继续解锁；不会出现两个不同版本或两套数据。
- **Spec**：`Requirement: 构建与分发`；`Requirement: 保持解锁`（ad-hoc 签名更新后的钥匙串行为，design D10）。

### [ ] M-04 卸载与彻底清除

- **操作**：先在应用内退出登录，从菜单栏菜单退出；在“系统设置 → 通用 → 登录项”移除“加密备份”；
  把应用拖到废纸篓；删除 `~/Library/Application Support/com.encryptedbackup.client`；
  在“钥匙串访问”搜索 `com.encryptedbackup.client` 并删除条目。
- **预期**：应用被删除；登录项不再存在；数据目录与钥匙串条目按文档清除；
  云端备份不受影响；重装后是干净状态。
- **Spec**：`Requirement: 保持解锁`（凭据清除）；安装 / 卸载约束（design D10）。

## B. 登录、待审核、解锁与钥匙串

### [ ] M-05 首次登录与钥匙串会话令牌

- **操作**：首次启动，使用已审核账号登录；打开“钥匙串访问”搜索 `com.encryptedbackup.client`。
- **预期**：进入文件页；钥匙串出现 service `com.encryptedbackup.client`、account `session-token` 的条目；
  默认没有 `master-key`；关于页版本 / 提交与 dmg 文件名一致。
- **Spec**：`Requirement: 登录与解锁`；`Requirement: 保持解锁`（会话令牌存钥匙串）。

### [ ] M-06 待审核账号没有写入口

- **操作**：退出登录，用待审核账号登录；管理员在网页后台通过后点“重新检查”。
- **预期**：显示“正在等待管理员审核”，没有上传、新建、备份文件夹入口；通过后进入文件页。
- **Spec**：`Requirement: 登录与解锁` → `Scenario: 待审核账号`。

### [ ] M-07 重新打开只需要密码解锁

- **操作**：退出应用后重新启动；输入密码解锁。
- **预期**：解锁页显示已保存邮箱；错误密码有提示；正确密码进入文件页；
  钥匙串中仍只有 `session-token`。
- **Spec**：`Requirement: 登录与解锁` → `Scenario: 重新打开应用`。

### [ ] M-08 退出登录清除会话与主密钥

- **操作**：先开启“保持解锁”，确认钥匙串出现 `master-key`；然后退出登录。
- **预期**：返回登录页；`session-token` 与 `master-key` 两个钥匙串条目都被删除；
  再打开应用需要重新输入邮箱与密码。
- **Spec**：`Requirement: 保持解锁` → `Scenario: 退出登录清除凭据`。

### [ ] M-09 钥匙串“仅本机、解锁时可用”属性

- **操作**：保持解锁后，在“钥匙串访问”中查看 `master-key` 条目的访问控制 / 属性；
  退出登录后确认删除；重启应用确认默认仍需密码。
- **预期**：主密钥存在钥匙串且仅限本机（不随 iCloud 同步、不进系统备份）；退出登录后删除；
  关闭保持解锁后重启不需要重新输入邮箱、但需要密码。
- **Spec**：`Requirement: 保持解锁`（macOS `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`，design D3）。

## C. 浏览、文件操作、上传下载与恢复

### [ ] M-10 浏览、筛选、排序与明文名称

- **操作**：网页版创建中文名 / 带重音字母的文件与子文件夹；客户端切换列表 / 网格、排序、筛选。
- **预期**：客户端显示正确明文名称与大小，无乱码；界面不出现密钥字段；路径按 `~/...` 显示。
- **Spec**：`Requirement: 文件管理`；`Requirement: 密钥只在 Rust 核心中`（桥接边界由自动化测试覆盖）。

### [ ] M-11 新建、重命名、移动、删除、回收站与版本

- **操作**：在客户端完成新建、重命名、移动、删除到回收站、恢复；在网页版上传同名新版本生成第二个版本，
  再在客户端版本历史中恢复旧版本；同时在网页版核对。
- **预期**：客户端与网页版状态一致；文件回到原位置；旧版本可恢复；无重复 / 丢失。
- **Spec**：`Requirement: 文件管理` → `Scenario: 删除并从回收站恢复`。

### [ ] M-12 客户端上传、Web 下载（SHA-256 一致）

- **操作**：在 Mac 客户端上传一张照片 / 中文名文件，在网页版下载并比较 SHA-256。
- **预期**：网页版能看到文件并下载，内容一致；上传进度、暂停 / 继续 / 取消 / 重试可用。
- **Spec**：`Requirement: 与 Web 互通` → `Scenario: 客户端上传、Web 下载`；
  `Requirement: 上传与下载`。

### [ ] M-13 Web 上传、客户端下载（SHA-256 一致）

- **操作**：网页版上传“合同.pdf”，客户端下载；比较 SHA-256。
- **预期**：客户端显示同名文件，内容一致；下载直接写到用户选择的路径。
- **Spec**：`Requirement: 与 Web 互通` → `Scenario: Web 上传、客户端下载`。

### [ ] M-14 重启后继续未完成的上传

- **操作**：上传 ≥ 2 GB 文件，进行到一半时退出客户端；重新打开并解锁，等待完成。
- **预期**：从已确认分块之后继续，不从 0 开始；完成后 SHA-256 一致；无重复文件。
- **Spec**：`Requirement: 上传与下载` → `Scenario: 重启后继续上传`。

### [ ] M-15 下载整个文件夹到本地

- **操作**：云端准备多层目录；客户端“下载文件夹到本地”到一个空目录。
- **预期**：目录结构完整，抽样 SHA-256 一致；无临时文件残留；失败时不留半成品。
- **Spec**：`Requirement: 上传与下载` → `Scenario: 下载文件夹到本地`。

### [ ] M-16 拖拽上传

- **操作**：从访达拖入单个文件、多个文件、一个文件夹；再拖入桌面之外路径的文件。
- **预期**：文件 / 文件夹上传成功并保留结构；未启用沙箱时任意位置的文件都可拖入；
  拖拽有反馈，不崩溃。
- **Spec**：`Requirement: 上传与下载`（拖拽上传）；macOS 专有项“未启用 App Sandbox”。

### [ ] M-17 暂停 / 继续 / 取消 / 重试与 429 退避

- **操作**：上传多个文件时暂停、继续、取消、重试；上传大量小文件触发限流。
- **预期**：各操作按预期生效；429 显示“等待限流”并自动退避，不把文件记为永久失败。
- **Spec**：`Requirement: 上传与下载`（暂停 / 继续 / 取消 / 重试、429 退避）。

## D. 文件夹备份全流程与 macOS 文件监听

### [ ] M-18 添加备份文件夹

- **操作**：添加一个测试目录，查看默认云端目标；可修改并保存。
- **预期**：默认目标为 `全部文件 / 电脑备份 / <设备名> / <本地文件夹名>`；说明本地删除不删除云端。
- **Spec**：`Requirement: 桌面文件夹备份`；`Requirement: 备份排除与控制`。

### [ ] M-19 FSEvents 监听：新增文件自动备份

- **操作**：向备份文件夹加入新文件；等待约 5 秒 + 防抖；在网页版查看。
- **预期**：文件自动出现在云端并可解密；托盘 / 菜单栏显示正在备份，完成后“已全部备份”。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 新增文件自动备份`；
  macOS 专有项“FSEvents 文件监听”。

### [ ] M-20 修改文件生成新版本

- **操作**：修改已备份文件并保存；查看版本历史并恢复旧版本。
- **预期**：新增版本，旧版本可恢复；内容一致。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 修改文件生成新版本`。

### [ ] M-21 本地删除不影响云端

- **操作**：本地删除已备份文件；等待监听与全量核对；网页版查看。
- **预期**：云端文件保留、版本不减少。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 本地删除不影响云端`。

### [ ] M-22 内容不变不产生新版本

- **操作**：只改修改时间、不改内容（`touch` 或 `SetFile` 等），等待自动核对与立即备份。
- **预期**：不上传、不产生新版本；只更新索引。
- **Spec**：`Requirement: 桌面文件夹备份` → `Scenario: 重复内容不产生版本`。

### [ ] M-23 排除临时文件

- **操作**：创建 `.DS_Store`、`Thumbs.db`、`desktop.ini`、`._x`、`report.docx.tmp`、`~$report.docx`、
  `a.part`、`b.crdownload`，以及自定义排除子文件夹。
- **预期**：这些都不上传；正常文件仍备份。
- **Spec**：`Requirement: 备份排除与控制` → `Scenario: 排除临时文件`。

### [ ] M-24 NFD 文件名规范化（macOS 专有）

- **操作**：在 Mac 上创建名为“简历.pdf”以及带重音字母（如 `é`）的文件，加入备份文件夹；
  在网页版与 Windows 客户端查看；随后在 Windows 客户端对同一云端文件夹备份同名文件。
- **预期**：云端只有一个“简历.pdf”，不出现 NFD / NFC 两份；Windows 上的同名文件作为新版本，
  而不是重复文件。
- **Spec**：`Requirement: 备份排除与控制` → `Scenario: macOS 文件名规范化`。

### [ ] M-25 被占用文件与上传中修改

- **操作**：用预览 / Office 等打开文件并保存；用 `lsof` 或 `chmod` 制造不可读 / 被占用场景；
  上传大文件时持续写入该文件。
- **预期**：能共享读时正常备份；不可读 / 被占用时本次失败或延后，其他文件继续；
  上传中内容变化时放弃并稍后重试，不产生截断文件。
- **Spec**：`Requirement: 桌面文件夹备份`；`Requirement: 上传与下载`（design D4）。

### [ ] M-26 暂停 / 恢复、立即备份与限速

- **操作**：暂停全部备份后放新文件；恢复；立即备份；设置上传限速。
- **预期**：暂停期间不上传；恢复后继续；立即备份触发扫描；限速生效。
- **Spec**：`Requirement: 备份排除与控制`。

### [ ] M-27 重命名不删除云端内容

- **操作**：本地重命名已备份文件；等待扫描。
- **预期**：云端保留旧文件并新增新名字文件；不删除旧内容。
- **Spec**：`Requirement: 桌面文件夹备份`（本地删除或重命名 MUST NOT 删除云端内容）。

## F. macOS 沙箱、开机启动与保持解锁

### [ ] M-33 未启用 App Sandbox：重启后仍能备份

- **操作**：添加“文稿”或桌面下的备份文件夹，完成首次备份；重启 Mac 并登录；
  不重新选择文件夹，向其中加入文件；再拖入任意位置（如下载目录）的文件。
- **预期**：重启后仍能读取原备份文件夹并自动备份；拖拽任意位置的文件可上传；
  不需要每次重新授权文件夹。
- **Spec**：`Requirement: 桌面文件夹备份`；macOS 专有项“未启用 App Sandbox（design D10）”。

### [ ] M-34 开机自动启动（未保持解锁）

- **操作**：设置中开启“开机自动启动”，关闭“保持解锁”；重启 Mac 并登录；观察菜单栏。
- **预期**：应用自动启动；菜单栏提示需要解锁；点击打开解锁页；
  系统设置 → 通用 → 登录项中出现“加密备份”。
- **已知限制**：macOS 上开机启动由 `MainFlutterWindow.swift` 用系统 `SMAppService` 实现（需要 macOS 13+；
  macOS 12 上开启会提示不支持）。系统登录项不会传入 `--background` 参数，所以开机时主窗口会显示出来
  （Windows 上只进托盘）。如果用户希望开机时只进菜单栏，记录为待改进项。
- **Spec**：`Requirement: 托盘与后台运行`；`Requirement: 保持解锁`（开机启动不涉及密钥）。

### [ ] M-35 保持解锁 + 开机启动自动继续备份

- **操作**：开启“保持解锁”（确认风险说明）与“开机自动启动”；重启 Mac 并登录；加入新文件。
- **预期**：自动启动、自动解锁；无需密码；备份继续，文件自动上传；钥匙串有 `master-key`。
- **Spec**：`Requirement: 保持解锁` → `Scenario: 开机后自动继续备份`。

### [ ] M-36 关闭保持解锁会移除主密钥
