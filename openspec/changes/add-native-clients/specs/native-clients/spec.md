# Spec Delta

## Purpose

定义 Windows 与 macOS 桌面原生客户端（Flutter 界面 + Rust 核心）的行为：与 Web 互通的认证、文件管理与传输，后台增量文件夹备份与托盘，以及密钥只存在于 Rust 核心的安全边界。

## ADDED Requirements

### Requirement: 与 Web 互通
原生客户端 SHALL 使用与 Web 相同的账号、API 与加密格式：任一端上传的文件 MUST 能在其他端浏览、解密与下载，名称、版本与回收站状态一致。

#### Scenario: Web 上传、客户端下载
- **WHEN** 用户在网页上传“合同.pdf”，随后在 Windows 客户端打开同一文件夹并下载
- **THEN** 客户端显示同名文件，下载内容的 SHA-256 与原文件一致

#### Scenario: 客户端上传、Web 下载
- **WHEN** 用户在 macOS 客户端上传一张照片
- **THEN** 网页上能看到该文件并下载得到相同内容

### Requirement: 登录与解锁
客户端 SHALL 支持邮箱与密码登录，密钥派生在 Rust 核心内完成；登录后会话令牌保存在系统钥匙串中，再次打开应用时只需输入密码解锁（或在开启“保持解锁”时自动解锁）。注册、忘记密码与恢复密钥重置 SHALL 通过打开网页完成。待审核账号登录后 MUST 显示等待审核说明，不提供上传入口。

#### Scenario: 重新打开应用
- **WHEN** 已登录的用户关闭并重新打开客户端（未开启“保持解锁”）
- **THEN** 客户端显示带邮箱的解锁页，输入密码后进入文件页，无需重新输入邮箱

#### Scenario: 待审核账号
- **WHEN** 待审核账号登录客户端
- **THEN** 显示“正在等待管理员审核”，没有上传与新建入口

### Requirement: 密钥只在 Rust 核心中
主密钥、节点密钥、内容密钥、`auth_key` 与恢复密钥 SHALL 只存在于 Rust 核心内存中；Flutter 界面层 MUST NOT 接收到任何密钥字节或可派生密钥的材料；文件明文由 Rust 直接读写本地路径，解密失败时 MUST NOT 留下部分明文文件。

#### Scenario: 桥接接口不暴露密钥
- **WHEN** 枚举全部 Rust→Dart 桥接接口的返回类型
- **THEN** 其中不含密钥或包裹密钥字段

#### Scenario: 下载校验失败
- **WHEN** 下载过程中某个密文块被篡改
- **THEN** 下载失败并提示原因，目标位置没有出现该文件（临时文件已清理）

### Requirement: 保持解锁
客户端 SHALL 提供默认关闭的“在这台电脑上保持解锁”：开启时主密钥交由系统钥匙串保管（macOS Keychain 仅本机，Windows DPAPI 当前用户），并在开启前说明风险；退出登录、修改密码或会话失效时 MUST 清除钥匙串中的会话与主密钥。

#### Scenario: 开机后自动继续备份
- **WHEN** 开启“保持解锁”与“开机自动启动”的电脑重启并登录系统
- **THEN** 客户端自动启动、自动解锁，备份继续进行，无需输入密码

#### Scenario: 退出登录清除凭据
- **WHEN** 用户在客户端退出登录
- **THEN** 钥匙串中本应用的会话令牌与主密钥都被删除，下次打开需要重新登录

### Requirement: 文件管理
客户端 SHALL 提供与 Web 一致的文件管理：浏览（列表 / 网格、排序、当前文件夹筛选）、新建文件夹、重命名、移动、删除到回收站、回收站恢复与永久删除、版本历史与恢复。

#### Scenario: 删除并从回收站恢复
- **WHEN** 用户在客户端删除一个文件，再在回收站中恢复
- **THEN** 文件回到原位置，网页上看到的状态与之一致

### Requirement: 上传与下载
客户端 SHALL 支持上传文件、上传文件夹与拖拽上传、下载文件、下载整个文件夹到本地（保留目录结构）；传输列表 SHALL 支持暂停、继续、取消、重试；应用重启后 MUST 继续未完成的上传；收到 429 时 MUST 自动退避而不计为失败。

#### Scenario: 重启后继续上传
- **WHEN** 上传一个 2 GB 文件到一半时退出客户端，随后重新打开并解锁
- **THEN** 上传从已确认的分块之后继续，而不是从头开始

#### Scenario: 下载文件夹到本地
- **WHEN** 用户在桌面客户端把云端文件夹“照片”下载到本地目录
- **THEN** 本地出现“照片”及其完整子目录结构，每个文件内容与云端一致

### Requirement: 桌面文件夹备份
客户端 SHALL 允许添加一个或多个本地备份文件夹，把新增与修改的文件自动增量备份到指定云端文件夹：监听文件变化并定时全量核对；大小与修改时间未变的文件 MUST 跳过；内容未变的文件 MUST NOT 产生新版本；修改的文件 MUST 作为新版本上传；本地删除或重命名 MUST NOT 删除云端内容。

#### Scenario: 新增文件自动备份
- **WHEN** 用户把一个新文件放进已添加的备份文件夹
- **THEN** 数秒后该文件出现在对应的云端文件夹中，托盘显示“已全部备份”

#### Scenario: 修改文件生成新版本
- **WHEN** 已备份的文件被修改并保存
- **THEN** 云端该文件新增一个版本，旧版本可在版本历史中恢复

#### Scenario: 本地删除不影响云端
- **WHEN** 用户在本地删除一个已备份的文件
- **THEN** 云端文件保留不变

#### Scenario: 重复内容不产生版本
- **WHEN** 文件的修改时间变化但内容与云端当前版本相同
- **THEN** 不上传、不产生新版本，只更新本地索引

### Requirement: 备份排除与控制
桌面客户端 SHALL 默认排除系统与临时文件、不跟随符号链接，并允许用户添加排除规则与排除子文件夹；SHALL 提供暂停 / 恢复、立即备份与上传限速。macOS 上的文件名 MUST 规范化为 NFC 后再与云端比较和上传。

#### Scenario: 排除临时文件
- **WHEN** 备份文件夹中出现 `report.docx.tmp` 与 `~$report.docx`
- **THEN** 它们不会被上传

#### Scenario: macOS 文件名规范化
- **WHEN** macOS 上备份名为“简历.pdf”（NFD 编码）的文件，之后在 Windows 上备份同一云端文件夹中的同名文件
- **THEN** 云端只有一个“简历.pdf”，后者作为新版本而不是重复文件

### Requirement: 托盘与后台运行
桌面客户端关闭主窗口后 SHALL 在托盘（Windows）/ 菜单栏（macOS）继续运行；托盘弹窗 SHALL 显示备份状态、进行中的传输、最近活动，并提供暂停 / 恢复、打开应用、打开网页版与退出；SHALL 支持默认关闭的开机自动启动；重复启动时 MUST 激活已有实例。

#### Scenario: 关闭窗口后继续备份
- **WHEN** 用户关闭主窗口后向备份文件夹添加文件
- **THEN** 文件仍被备份，托盘图标显示正在上传

#### Scenario: 未解锁时提示
- **WHEN** 未开启“保持解锁”的客户端在开机自动启动后
- **THEN** 托盘提示“需要解锁才能继续备份”，点击后打开解锁页

### Requirement: 构建与分发
CI SHALL 在每次提交时检查 Rust 核心与 Flutter 代码，并构建 Windows 安装包与 macOS .dmg（ad-hoc 签名）作为可下载产物；客户端 SHALL 在“关于”中显示版本号与对应的提交。

#### Scenario: 下载 Windows 安装包
- **WHEN** 用户从 CI 产物下载 Windows 安装包并安装
- **THEN** 首次运行（在 SmartScreen 中选择“仍要运行”后）可以正常登录与使用
