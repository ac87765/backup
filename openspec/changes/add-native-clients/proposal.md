# Proposal

## Why

Web 版已经稳定上线，但“备份”这件事最需要的是不用打开网页、在后台自动完成：电脑上的工作资料、照片目录有变化时自动加密上传。浏览器做不到可靠的后台备份，也受“每次都由服务端下发代码”的信任限制（见“安全与隐私”页）。原生客户端可以把客户端代码固定在本机，同时提供后台备份能力。

## What Changes

新增桌面原生客户端：**Windows 与 macOS**，技术栈 **Flutter（界面）+ Rust（核心）**。路线图：本 change（桌面端）→ `add-wechat-backup`（微信备份，桌面端）→ `add-ios-client`（iOS，复用本 change 的 Rust 核心与 Flutter 工程）。

- **共享 Rust 客户端核心 `client-core`**：复用 Web 已在用的 `crypto-core`（同一套加密格式与测试向量），加上 API 客户端、认证与密钥管理、上传下载管线、文件夹扫描与增量判定、本地状态库。界面层不接触任何密钥；结构上同时为之后的 iOS 客户端准备（不依赖桌面专有 API 的部分与桌面功能分开）。
- **通用功能**：登录 / 解锁、等待审核提示、文件浏览（列表 / 网格、排序、当前文件夹筛选）、新建文件夹、重命名、移动、删除到回收站、回收站恢复与永久删除、版本历史与恢复、上传（含文件夹与拖拽）、下载、传输列表（暂停 / 继续 / 取消 / 重试，限流自动退避）、退出登录。注册、忘记密码与恢复密钥重置在网页完成（客户端提供跳转）。
- **文件夹备份**：
  - 选择一个或多个本地文件夹，自动把新增和修改的文件增量备份到云端（单向；不会因本地删除而删除云端；修改作为新版本保留）。
  - 监听文件变化 + 定时全量核对；排除规则（系统文件 + 自定义）；暂停 / 恢复；上传限速。
  - 托盘（Windows）/ 菜单栏（macOS）弹窗：备份状态、最近活动、暂停、打开应用。
  - 关闭窗口后在后台继续运行；可选开机自动启动；首次启动引导选择备份文件夹。
  - 恢复：把云端任意文件夹整体下载到本地（保留目录结构，不打包成 zip；同名文件可选保留两份 / 覆盖 / 跳过）。
- **可选“保持解锁”**：后台备份需要在重启后继续工作，因此提供默认关闭的“在这台电脑上保持解锁”，把主密钥交给系统钥匙串（macOS Keychain / Windows DPAPI）保管，并如实说明风险。
- **分发（自用为主）**：Windows 安装包与 macOS .dmg 由 CI 构建（未签名 / ad-hoc 签名，首次打开需手动允许）。
- **服务端**：不需要新增接口；客户端通过 `User-Agent` 标识自身，便于在“登录设备”中区分。

## Capabilities

### New Capabilities

- `native-clients`：桌面原生客户端的认证与密钥边界、文件管理、传输、文件夹备份、托盘与后台运行、分发。

### Modified Capabilities

无。客户端完全复用现有 API 与加密格式；`client-encryption`、`file-transfer`、`folder-transfer` 的行为契约同样适用于原生客户端。

## Impact

- 新增 `crates/client-core`（Rust 客户端核心）、`apps/client`（Flutter 工程，含 `rust/` 桥接 crate，flutter_rust_bridge 生成 Dart 绑定；启用 Windows 与 macOS 平台，iOS 平台在 `add-ios-client` 中启用）。
- CI 新增：Rust 客户端核心测试（连接测试服务端）、Flutter 静态检查与组件测试、Windows 构建（windows 运行器）、macOS 构建（macos 运行器，ad-hoc 签名）。
- 设计稿：仓库内 `design/desktop/` 的静态 HTML 界面稿（与 Web 共用设计令牌）及其截图，实现以 HTML 源码中的数值与文案为准。
- 开发机没有 Mac：macOS 的编译由 CI 保证，实际运行验收依赖用户本人的 Mac。
