# Spec Delta

## Purpose

定义桌面客户端的发布与更新：维护者离线签名的版本清单、服务器提供的下载目录、客户端验签后的更新安装，以及网站上的公开下载页面。

## ADDED Requirements

### Requirement: 签名的发布清单
每个客户端版本 SHALL 发布一份列出各平台安装包文件名、大小与 SHA-256 的版本清单，并附带由维护者离线私钥生成的 Ed25519 签名；签名私钥 MUST NOT 存放在仓库、CI 或服务器上。

#### Scenario: 发布新版本
- **WHEN** 维护者为标签 `v0.2.0` 运行发布脚本
- **THEN** 服务器下载目录中出现该版本的 Windows 与 macOS 安装包、更新后的 `latest.json` 与签名，签名可以用仓库中公布的公钥验证

#### Scenario: 私钥不离开维护者电脑
- **WHEN** 检查仓库内容、CI 配置与服务器文件
- **THEN** 找不到发布签名私钥

### Requirement: 客户端检查更新
桌面客户端 SHALL 在启动后与每 24 小时检查一次版本清单，并 MUST 用内置公钥验证签名；签名无效、清单格式未知或版本不高于当前版本时 MUST NOT 提示或下载更新；检查请求 MUST NOT 携带用户凭据。

#### Scenario: 发现新版本
- **WHEN** 服务器上有签名有效、版本高于当前的清单
- **THEN** 设置“关于”、托盘菜单与主窗口横幅提示新版本及更新内容

#### Scenario: 被篡改的清单
- **WHEN** 服务器上的 `latest.json` 被修改但签名未变
- **THEN** 客户端不提示更新，也不下载任何文件

#### Scenario: 旧清单不能诱导降级
- **WHEN** 服务器把清单换回一个更早的、签名有效的版本
- **THEN** 客户端不把它当作更新

### Requirement: 安装更新
用户确认后，客户端 SHALL 下载对应平台的安装包，MUST 校验大小与 SHA-256 与已验签清单一致后才运行或替换应用；安装完成后 SHALL 重新启动客户端，本地数据、备份设置与凭据保持不变。

#### Scenario: Windows 一键升级
- **WHEN** 用户在 Windows 客户端点“下载并安装”
- **THEN** 客户端下载并校验安装包，退出后静默安装并自动重新启动为新版本，无需管理员权限，备份文件夹与登录状态保留

#### Scenario: macOS 一键升级
- **WHEN** 用户在 macOS 客户端点“下载并安装”
- **THEN** 客户端校验 .dmg 后替换应用并重新启动为新版本；无法替换时打开 .dmg 并提示用户拖到“应用程序”

#### Scenario: 安装包被篡改
- **WHEN** 下载的安装包 SHA-256 与清单不一致
- **THEN** 客户端删除该文件、不运行它，并提示下载的文件不完整或被篡改

### Requirement: 强制更新
当前版本低于已验签清单中的最低支持版本时，客户端 SHALL 显示“需要更新后才能继续使用”，只提供下载并安装与打开下载页面，MUST NOT 删除本地数据或凭据。

#### Scenario: 版本过旧
- **WHEN** 客户端版本为 0.1.0，而清单的最低支持版本为 0.2.0
- **THEN** 客户端显示需要更新的页面，更新后恢复正常使用

### Requirement: 公开下载页面
网站 SHALL 提供无需登录的下载页面，识别访问者的系统并突出对应平台的下载按钮，同时列出另一平台、版本、发布日期、大小、SHA-256、系统要求、首次打开说明与最近的更新内容；无法读取版本清单时 MUST 显示“暂时无法获取最新版本”而不是过时或错误的信息。

#### Scenario: Windows 访问者
- **WHEN** 用户用 Windows 电脑的浏览器打开 `/download`
- **THEN** 主按钮为“下载 Windows 版”，并显示 macOS 版的次要入口、版本信息与 SmartScreen 放行说明

#### Scenario: 手机访问者
- **WHEN** 用户用手机打开 `/download`
- **THEN** 页面在手机宽度下正常排版，说明客户端适用于 Windows 与 macOS、iOS 即将推出

#### Scenario: 清单不可用
- **WHEN** 服务器上暂时没有 `latest.json`
- **THEN** 页面提示暂时无法获取最新版本并提供重试
