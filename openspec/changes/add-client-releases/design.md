# Design

## Context

- 桌面客户端（`add-native-clients`）的 CI 已能在 `main` 与 `v*` 标签上产出 Windows 安装包（Inno Setup，按用户安装，`AppId` 固定）与 macOS universal .dmg（ad-hoc 签名，未启用沙箱）。版本号由 `git describe` 注入 `APP_VERSION`。
- 服务器：阿里云 ECS（`/opt/backup`，Caddy 在宿主机做 HTTPS 反向代理到 `127.0.0.1:8080`），用户量很小（约 2 人）。
- 威胁模型沿用产品原则：服务器不可信（可能被入侵或被替换内容），客户端是信任根。

## Goals / Non-Goals

**Goals：** 用户能在网站上找到并下载客户端；已安装的客户端能发现新版本并一键升级；被入侵的服务器无法让客户端安装未经维护者签名的程序。

**Non-Goals：** Apple 公证 / Windows 代码签名证书（需要付费，另议）；增量补丁（每次下载完整安装包）；自动静默升级（必须用户确认）；iOS 更新（App Store / TestFlight 自行处理）；多渠道（测试版 / 正式版）。

## Decisions

### D1 版本与清单

- 版本号使用语义化版本，来自 git 标签 `vX.Y.Z`（首个正式版 `v0.1.0`）。非标签构建的版本号形如 `0.1.0-dev+<sha>`，不会被当作可升级目标。
- 发布清单 `latest.json`（UTF-8 JSON）：
  ```json
  {
    "schema": 1,
    "version": "0.2.0",
    "released_at": "2026-11-05T10:00:00Z",
    "min_supported": "0.1.0",
    "notes": ["支持微信备份", "托盘菜单修复"],
    "history": [
      { "version": "0.1.0", "released_at": "2026-11-01T10:00:00Z", "notes": ["首个版本"] }
    ],
    "platforms": {
      "windows-x64": { "file": "EncryptedBackup-0.2.0-windows-x64.exe", "size": 15400000, "sha256": "<64 hex>" },
      "macos-universal": { "file": "EncryptedBackup-0.2.0-macos.dmg", "size": 38500000, "sha256": "<64 hex>" }
    }
  }
  ```
- `history`：之前最多 2 个版本的版本号、日期与更新内容（发布脚本从上一份 `latest.json` 继承），供下载页面显示最近 3 个版本的更新日志；客户端只用于展示，不据此安装。
- 签名：`latest.json.sig` = 对 `latest.json` 原始字节的 Ed25519 签名（Base64）。客户端只接受签名有效、`schema` 已知、版本号可解析的清单；验证失败时视为“无法检查更新”，不提示、不下载。
- 防回滚：客户端只接受版本号**高于**当前版本的清单作为更新；清单中的 `version` 低于客户端已见过的最高版本时忽略（记录在本地状态库），防止服务器用旧的已签名清单诱导降级。

### D2 签名密钥（硬性）

- 维护者在开发机上生成 Ed25519 密钥对；**私钥只保存在维护者的电脑上**（例如 `%USERPROFILE%\.backup-release\release-signing.key`，权限仅本用户）并由用户另做离线备份（U 盘 / 密码管理器）。私钥 MUST NOT 进入仓库、CI secrets、服务器或日志。
- 文件格式：私钥文件为 32 字节 Ed25519 种子的标准 Base64（一行）；公钥文件为 32 字节公钥的标准 Base64（一行）。
- 公钥以常量形式编译进客户端（`client-core`），并写入仓库 `deploy/release-signing.pub` 供核对（测试保证两者一致）。
- 轮换：新版本客户端可以同时内置“当前公钥 + 下一把公钥”，由旧密钥签名的版本完成过渡；私钥丢失时只能让用户手动重装新版本（在下载页面说明）。

### D3 发布流程（维护者在开发机上执行）

1. 合并到 `main`，打标签 `vX.Y.Z` 并推送；CI（`client.yml`）在标签上构建并上传 Windows / macOS 产物。
2. 运行 `deploy/release-client.ps1 -Tag vX.Y.Z -Notes <文件>`：用 `gh` 下载该标签运行的产物 → 按清单命名 → 计算大小与 SHA-256 → 生成 `latest.json` → 用本地私钥签名 → 本地自检（用公钥验签、重新计算哈希）→ 通过 `scp` 上传安装包到 `/opt/backup/downloads/<版本>/`，最后原子替换 `latest.json` 与 `.sig`（先传临时名再 `mv`）。
3. 保留最近 3 个版本的安装包，更早的由脚本清理。
- 新增依赖：`ed25519-dalek`（RustCrypto 生态、纯 Rust、BSD-3/MIT 兼容，满足 `cargo deny`），用于客户端验签与发布工具签名；发布签名工具是仓库内一个小的 Rust 二进制（`cargo run -p release-tool -- sign`），避免依赖 OpenSSL 版本差异。

### D4 服务器下载目录

- Caddyfile 模板在反向代理之前加 `handle_path /downloads/*`：`root * /opt/backup/downloads`、`file_server`；`latest.json` 与 `.sig` 设 `Cache-Control: no-cache`，版本目录内的安装包设长期缓存（文件名含版本号，不会变化）。
- 下载目录只由发布脚本写入；服务端程序与数据库不变。安装包为公开内容（与 GitHub 仓库公开一致），不涉及用户数据。
- 网页 CSP：下载页面同源读取 `/downloads/latest.json`，无需放宽 CSP。

### D5 客户端检查与安装（桌面）

- 检查时机：启动后 10 秒、之后每 24 小时、设置“关于”中手动“检查更新”。只发两个请求（`latest.json` 与 `.sig`），不附带任何用户信息与 Cookie。
- 有新版本：设置“关于”显示新版本与更新内容；托盘菜单增加“有新版本 X.Y.Z”；主窗口顶部出现一条可关闭的横幅（每个版本只提示一次，用户关闭后在“关于”中仍可看到）。
- 安装：用户点“下载并安装” → 下载到临时目录（显示进度，可取消）→ 校验大小与 SHA-256（来自已验签清单）→
  - Windows：提示即将重启应用 → 停止备份引擎 → 以 `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS` 启动安装包并退出自身；安装包完成后重新启动应用（`[Run]` 段，静默模式下也执行）。按用户安装，不需要管理员权限。
  - macOS：停止备份引擎 → 挂载 .dmg（`hdiutil attach -nobrowse`）→ 用 `ditto` 把新的 `.app` 复制到当前应用所在位置的临时名，再原子替换 → 卸载 .dmg → 重新启动。无法写入应用目录时退回为“打开 .dmg 让用户拖动”。
- 强制更新：当前版本低于已验签清单的 `min_supported` 时，登录 / 主窗口显示阻断页“需要更新后才能继续使用”，只提供“下载并安装”与“打开下载页面”；本地已有数据与凭据不受影响。
- 失败处理：下载中断可重试；校验失败删除文件并提示“下载的文件不完整或被篡改”，不运行。

### D6 下载页面（网站）

- 公开路由 `/download`，未登录可访问；登录页底部、网页版设置、桌面客户端“关于”链接到它。
- 内容：标题与一句话卖点；按 `navigator.userAgent` 识别系统，主按钮为对应平台（Windows / macOS），旁边是另一平台的次按钮；版本、发布日期、大小、SHA-256（可复制）与“如何校验”；系统要求（Windows 10/11 64 位；macOS 12 及以上，开机启动需 13 及以上；Apple 芯片与 Intel 均可）；首次打开的图文步骤（SmartScreen“更多信息 → 仍要运行”；Gatekeeper 右键“打开”）；更新日志（来自清单 `notes`，最近 3 个版本）；iOS“即将推出”；隐私说明（客户端在本机加密）。
- 清单读取失败时显示“暂时无法获取最新版本”，提供重试，不显示错误的版本信息。下载页面只显示服务器上的信息，安装包完整性由客户端验签与用户核对 SHA-256 保证（首次下载无法由网页证明真实性，在页面说明“如何校验”）。
- 视觉按 `design/web/download.html`，沿用网页版设计令牌（与桌面一致的品牌蓝渐变面板、卡片、按钮），桌面与手机宽度自适应；动效遵守“减少动态效果”。

## Risks / Trade-offs

- **没有代码签名证书**：SmartScreen / Gatekeeper / 杀毒软件（如火绒）仍会提示，自动更新安装包也可能被拦截 → 页面与客户端给出放行说明；购买证书另议。
- **首次下载的真实性**：网页本身来自服务器，被入侵的服务器可以替换首次下载 → 公钥与 SHA-256 同时发布在 GitHub 仓库与 Release 说明中，页面提示可以对照；之后的更新由客户端验签保护。
- **私钥丢失**：无法再发布可自动安装的更新 → 强调离线备份；必要时发布内置新公钥的版本并让用户手动重装。
- **macOS 替换正在运行的应用**：先退出再由一个短小的辅助脚本完成替换与重启，失败退回手动拖动。

## Migration Plan

先实现服务器下载目录与发布脚本（不影响现有功能），再发布第一个带更新能力的客户端版本 `v0.1.0`（用户需手动安装这一次），之后的版本由客户端自动提示更新。部署 Caddy 配置变更需要用户同意写入服务器。
