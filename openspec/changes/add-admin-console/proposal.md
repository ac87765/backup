# Proposal

## Why

服务已经在公网运行，任何人都能注册并立即开始占用存储。运营者（目前只有一位）需要：控制谁能真正使用服务（注册后经批准才可使用），按用户调整存储额度，在发现滥用时停用账号，并能看到用户、用量与系统健康的总体情况。目前这些只能直接改数据库，既不安全也不方便。

## What Changes

- **账号审批**：新增账号状态 `pending / active / suspended / rejected`。默认注册模式为“需要审批”：新用户可以注册、验证邮箱、登录，但在管理员批准前只能看到“等待审核”页面，不能上传或创建任何内容。管理员批准时设定额度。现有账号迁移为 `active`。
- **注册模式**：管理员可切换 `需要审批`（默认）/ `开放注册` / `关闭注册`。
- **管理后台**（`/admin`，仅管理员可见入口与接口）：
  - 概览：各状态用户数、待审核数、总用量/总额度、近 7 天注册数、发信队列与对象删除队列积压、服务健康。
  - 用户管理：按状态筛选、按邮箱搜索；查看注册/验证/最近活动时间、用量与额度、文件与版本数量、登录设备；批准（设定额度）、拒绝、停用/恢复、修改额度、注销其全部会话。
  - 设置：注册模式、新用户默认额度。
  - 审计日志：所有管理操作（谁、何时、对谁、做了什么、来源 IP）。
- **管理员身份**：只能在服务器上用命令行授予或撤销（`server admin grant <email>` / `revoke`），网页与接口都无法提权。管理操作要求会话在最近 12 小时内完成过密码登录，否则要求重新登录。
- **邮件通知**：有新用户等待审核时通知管理员；账号被批准时通知用户。
- **防滥用**：每个 IP 每小时最多 5 次注册（在现有认证限流之外）。
- **隐私边界不变**：管理员只能看到账号与用量等元数据，看不到任何文件名或文件内容（服务器本身也没有）。

## Capabilities

### New Capabilities

- `admin-console`：管理员身份、管理接口、管理后台界面、审计日志、注册模式设置。

### Modified Capabilities

- `user-accounts`：新增账号审批与账号状态相关需求（注册后待审批、停用、拒绝、等待审核页面、注册限流）。

## Impact

- 数据库：迁移 `0006_admin.sql`（`users.status`、`users.is_admin`、审批相关列，`app_settings`、`admin_audit_log` 表）。
- 服务端：账号状态检查接入现有认证提取器；新增 `/api/v1/admin/*`；`server admin` 子命令；新邮件类型。
- 前端：等待审核页；`/admin` 管理后台（沿用 redesign-web-ui 设计规范）；账号菜单中管理员可见“管理后台”入口。
- 部署：迁移后用 `server admin grant tlj978626571@gmail.com` 授予管理员。
