# Proposal

## Why

用户的核心诉求是“备份文件夹”：把电脑上的一个目录（照片、工作资料等）连同子目录结构一起备份上去，过一段时间再备份一次时只更新变化的部分；需要时把整个文件夹拿回来。当前 Web 端只能逐个选择文件上传，子目录结构会丢失，也不能整体下载一个文件夹，离“备份”还差关键一步。

## What Changes

- 上传菜单新增“上传文件夹”；支持把文件夹直接拖进页面。保留完整的子目录结构（含空文件夹，浏览器能提供时）。
- 再次备份同一个文件夹时：同名文件夹合并；同名文件作为该文件的新版本上传（旧版本可在版本历史中恢复）；内容未变化的文件跳过，不产生新版本。
- 自动忽略系统垃圾文件（`.DS_Store`、`Thumbs.db`、`desktop.ini` 等）；名称不合法的项跳过并在结果中列出。
- 开始前做一次预检：文件数、总大小、剩余配额；超出配额时提示，不开始上传。
- 传输面板按“文件夹任务”分组显示总体进度（已完成/总数、字节进度），可展开查看单个文件，可整体取消、对失败项一键重试；结束时给出摘要（新增、更新、跳过、失败）。
- 客户端在收到 `429 rate_limited` 时按 `Retry-After` 自动等待后继续，不把限流当作失败。
- 文件夹（包括“全部文件”根目录）可整体下载为 `.zip`：浏览器逐个解密、边解密边流式打包，不把整个文件夹放进内存；保留子目录结构与空文件夹；支持 4 GiB 以上（ZIP64）。
- 生产配置把每用户写接口限流上调到 1200 次/分钟（已有配置项，无代码改动）。

## Capabilities

### New Capabilities

- `folder-transfer`：文件夹的批量上传（结构保留、增量备份、预检、分组进度）与整体打包下载。

### Modified Capabilities

无。单文件上传/下载、版本、配额、加密协议保持不变；文件夹功能完全由客户端编排现有接口实现。

## Impact

- 代码：`web/src/files/`（文件夹遍历、任务编排、zip 流式打包）、`web/src/worker/transfer-client.ts`（429 退避、版本上传复用、内容摘要比较）、传输面板与上传菜单；`crates/crypto-core` 与 `crypto-wasm` 的版本元数据增加一个可选字段（向后兼容，不改 AAD/帧格式）。服务端无代码改动。
- 依赖：新增 `client-zip`（MIT，约 6 KB gzip，流式 ZIP/ZIP64 生成，无网络访问）。
- 部署：生产环境 `BACKUP_USER_WRITE_RATE_LIMIT_PER_MINUTE=1200`。
