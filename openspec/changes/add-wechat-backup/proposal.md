# Proposal

## Why

对国内用户来说，电脑上最怕丢、也最难手动备份的往往是微信：聊天里收到的合同、图片、视频，以及聊天记录本身。微信的数据散落在一个深层目录里，按账号分开，普通用户不知道在哪、也不知道哪些该备份。把它做成桌面客户端的一项“一键备份”，是这个产品相对通用网盘的特色。

## What Changes

在桌面客户端（`add-native-clients`，Windows 先做，macOS 随后）中新增“微信备份”：

- **发现账号**：扫描本机微信的数据目录（兼容微信 3.x 与 4.x 的目录结构，以及用户自定义的存储位置），列出找到的账号文件夹（显示账号目录名、数据大小、最近活动时间，用户可自定义备注名）；找不到时可手动选择目录。
- **按类别选择备份内容**（每个账号单独选择）：
  - 聊天文件（收到 / 发送的文档等，普通文件，网页上可直接预览下载）；
  - 图片与视频（按微信自身的存储格式原样备份）；
  - 聊天记录数据库（作为不透明文件原样备份，用于恢复到微信；**不解密、不解析**）；
  - 手机聊天记录迁移备份（微信电脑版“备份与恢复”生成的备份文件，如存在）。
- **备份方式**：复用桌面备份引擎的增量上传；聊天记录数据库只在微信**退出时**备份，并以“快照”形式保存（保证同一快照内各文件一致），默认保留最近 3 份，更早的移入回收站。
- **恢复**：在微信退出时，把选中的类别恢复到原账号目录（文件类合并、跳过已存在；数据库快照替换前先把本机现有数据库移到旁边保留）。
- **明确不做**：不解密微信数据库、不读取微信进程内存、不按单个聊天选择、不在网页上查看聊天内容、不修改微信目录中的任何文件（恢复除外，且需用户确认）。原因：法律与平台条款风险、随微信版本变化极易失效，并且与“我们看不到你的数据”的产品承诺一致——客户端也只做原样搬运。

## Capabilities

### New Capabilities

- `wechat-backup`：微信数据目录发现、按类别备份、数据库快照、恢复，以及不解密的边界。

### Modified Capabilities

无。依赖 `native-clients` 的备份引擎（add-native-clients design D6），不改变其行为。

## Impact

- `crates/client-core` 新增 `wechat` 模块（`desktop` feature 下）：目录发现、类别规则、进程检测、快照与恢复。
- Flutter：侧边栏新增“微信备份”页面、账号卡片、类别选择、恢复对话框。
- Figma：新增微信备份页面与恢复流程设计（实施前绘制并经用户确认）。
- 服务端：无改动。数据量可能很大（几十 GB），开始前显示预计大小与剩余配额。
