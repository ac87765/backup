# Spec Delta

## Purpose

定义客户端加密的密钥体系、算法、密文格式，以及服务端能够看到的信息边界。它保证服务端、OSS 和数据库的任何泄露都不会暴露文件内容、文件名或用户密钥。

## ADDED Requirements

### Requirement: 所有加解密在客户端执行
文件内容、文件名、文件元数据的加密与解密 SHALL 只在客户端执行。服务端 MUST NOT 接收或存储任何明文内容、明文文件名、主密钥、节点密钥、恢复密钥或用户密码。

#### Scenario: 审计上传请求
- **WHEN** 检查一次完整上传过程中客户端发往服务端与 OSS 的全部请求
- **THEN** 其中不包含文件明文、明文文件名或任何未被包裹的密钥

### Requirement: 主密钥与密码派生
每个账号 SHALL 拥有一把在客户端用 CSPRNG 生成的 256 位主密钥（MK）。客户端 MUST 用 Argon2id（默认 m=64 MiB, t=3, p=1，16 字节随机盐）从密码派生根密钥，再用 HKDF-SHA256 以不同 info 派生出“密码包裹密钥”与“认证密钥”，两者 MUST 互相独立。MK 由密码包裹密钥用 AEAD 包裹。

#### Scenario: 认证密钥无法推出包裹密钥
- **WHEN** 攻击者获得了认证密钥（例如从网络中截获）
- **THEN** 他无法据此计算出密码包裹密钥，也无法解包 MK

#### Scenario: KDF 参数随账号存储
- **WHEN** 系统将来提高默认 Argon2id 参数
- **THEN** 已有账号仍按其存储的参数派生密钥并能正常登录，并在下次修改密码时升级到新参数

### Requirement: KDF 参数校验
KDF 参数 SHALL 以带算法标识的结构存储与传输（当前唯一算法为 `argon2id`）。客户端在派生前 MUST 校验算法标识与参数范围（内存 64–256 MiB、迭代 3–8、并行度 1），不满足时拒绝派生且不向服务端发送任何派生值。

#### Scenario: 被降级的参数
- **WHEN** 登录前置查询返回内存代价 8 MiB、迭代 1 次的参数
- **THEN** 客户端拒绝派生并提示安全错误，不发送认证密钥

#### Scenario: 过大的参数
- **WHEN** 返回的内存代价为 1 GiB
- **THEN** 客户端拒绝派生，不分配该内存

#### Scenario: 未知算法
- **WHEN** 参数中的算法标识不是 `argon2id` 或缺失
- **THEN** 客户端拒绝派生并提示需要升级客户端

### Requirement: 恢复密钥
客户端 SHALL 在注册时生成 256 位随机恢复密钥，并以人类可抄写的编码（分组的 Base32 加校验位）展示。MK MUST 另外被恢复密钥派生的包裹密钥包裹一份；恢复密钥同时用 HKDF 派生出一个恢复认证值供服务端校验。

#### Scenario: 抄写错误被检测
- **WHEN** 用户输入的恢复密钥有一个字符抄错
- **THEN** 客户端通过校验位在本地发现错误并提示，不发送请求

### Requirement: 节点密钥
每个文件和文件夹 SHALL 拥有独立的 256 位随机节点密钥，由 MK 以 AEAD 包裹后存储于服务端，包裹时的附加认证数据（AAD）MUST 绑定节点 ID，防止服务端把一个节点的包裹密钥挪用到另一个节点。

#### Scenario: 服务端调换包裹密钥
- **WHEN** 恶意服务端把节点 A 的包裹密钥返回为节点 B 的
- **THEN** 客户端解包认证失败，拒绝使用该密钥并报告完整性错误

### Requirement: 认证加密算法
所有对称加密 SHALL 使用 XChaCha20-Poly1305，每次加密使用 CSPRNG 生成的 24 字节随机 nonce。密文 MUST 带有格式版本号，以便将来演进算法。

#### Scenario: 篡改密文
- **WHEN** 任意一个字节的密文、nonce 或 AAD 被修改
- **THEN** 解密失败，客户端不输出任何部分明文

#### Scenario: 未知格式版本
- **WHEN** 客户端遇到不支持的格式版本号
- **THEN** 客户端报告“需要升级客户端”，而不是尝试解密

### Requirement: 分块内容加密
文件内容 SHALL 按固定明文块大小（4 MiB，最后一块可更小）分块加密。每次上传产生一个内容对象（content），每块的 AAD MUST 绑定内容 ID、块序号、总块数以及“是否最后一块”标志，以防止块被重排、替换、截断或拼接到其他内容。

#### Scenario: 块顺序被调换
- **WHEN** 服务端交换返回第 2 块和第 3 块的密文
- **THEN** 客户端解密失败并报告完整性错误

#### Scenario: 块被拼接到其他内容
- **WHEN** 服务端把另一个文件的块当作本文件的块返回
- **THEN** 客户端解密失败并报告完整性错误

#### Scenario: 文件被截断
- **WHEN** 服务端只返回前 N-1 块并声称文件只有 N-1 块
- **THEN** 客户端因最后一块标志或总块数不匹配而报告完整性错误

#### Scenario: 空文件
- **WHEN** 用户上传 0 字节文件
- **THEN** 客户端产生恰好一个加密的空块，下载解密后得到 0 字节文件

### Requirement: 版本与内容绑定
版本元数据 SHALL 在加密明文中包含该版本所引用内容的 ID 与明文总大小。下载任一版本时，客户端 MUST 校验解密出的内容 ID 等于服务端所给内容，并在解密完成后校验明文总长度等于记录的大小，任一不符即按完整性错误处理且不保存文件。

#### Scenario: 版本被指向旧内容
- **WHEN** 服务端把文件的当前版本指向该文件更早一次上传的内容
- **THEN** 客户端发现版本元数据中的内容 ID 不匹配，报告完整性错误

#### Scenario: 明文大小不符
- **WHEN** 解密后的明文总长度与版本元数据中的大小不一致
- **THEN** 客户端报告完整性错误并丢弃已写出的部分

#### Scenario: 恢复旧版本后下载
- **WHEN** 用户把文件恢复到旧版本后下载当前版本
- **THEN** 新版本的元数据指向被恢复的内容，校验通过，下载内容与旧版本一致

### Requirement: 元数据加密
文件名、MIME 类型、原始修改时间和明文大小 SHALL 作为一个加密元数据对象，用节点密钥加密存储。文件夹名同样加密。

#### Scenario: 数据库泄露
- **WHEN** 攻击者获得完整数据库副本
- **THEN** 他无法得知任何文件名或文件夹名

### Requirement: 同名检测令牌
为在不暴露文件名的前提下保证同一文件夹内名称唯一，客户端 SHALL 为每个节点计算名称令牌：HMAC-SHA256(由 MK 派生的名称密钥, 父节点 ID ‖ Unicode NFC 规范化且转小写的名称)。服务端仅比较令牌是否相等。

#### Scenario: 同一文件夹内重名
- **WHEN** 用户在同一文件夹内创建与已有文件同名（忽略大小写）的文件
- **THEN** 服务端因令牌冲突拒绝，并由客户端提示重名

#### Scenario: 不同文件夹内同名
- **WHEN** 用户在两个不同文件夹中各放一个 `report.pdf`
- **THEN** 两者令牌不同，均可创建

### Requirement: 服务端可见信息边界
系统 SHALL 在用户文档中明确列出服务端能看到的信息：账号邮箱、文件夹树结构（节点数量与父子关系）、每个版本的密文大小与块数、创建/修改/删除时间、访问时间与 IP。除此之外的信息 MUST NOT 以明文形式发送给服务端。

#### Scenario: 用户查看隐私说明
- **WHEN** 用户打开“安全与隐私”页面
- **THEN** 页面列出上述服务端可见信息清单，并说明 Web 版 E2EE 依赖于服务端下发的前端代码未被篡改

### Requirement: 密钥只存在于内存
解包后的 MK 与节点密钥 SHALL 只保存在 Web Worker 的内存中，MUST NOT 写入 localStorage、sessionStorage、IndexedDB 或 Cookie。不再使用的密钥缓冲区 MUST 被清零。

#### Scenario: 登出后检查存储
- **WHEN** 用户登出后检查浏览器全部存储
- **THEN** 找不到任何密钥材料

### Requirement: 跨实现兼容
加密格式 SHALL 由一组固定测试向量（输入密钥、nonce、明文、AAD 与期望密文）定义；所有客户端实现（浏览器 WASM、将来的桌面端）MUST 通过同一组测试向量。

#### Scenario: 测试向量回归
- **WHEN** 加密实现被修改
- **THEN** 若输出与测试向量不一致，CI 失败
